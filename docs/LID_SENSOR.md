# 蓋の磁気センサー(2026-11-20 に組み込んだ。実機の照射での確認はまだ)

蓋の磁気センサーで、アプリからの X線照射を許可・不許可にする。**ソフトの側の安全装置**で、機器そのものの仕組みではない(本体のトリガーを手で引けば、蓋が開いていても照射できる。アプリが固まった・落ちたときにトリガーを離せないのも今と同じ)。

## センサー(調べ済み)

| 項目 | 内容 |
|---|---|
| 機器 | USB 413d:2107(PCsensor 系の、キーボードのふりをするスイッチ。COM ポートではない)。製造元・製品名の文字列は空 |
| 中身 | インターフェース 0 = キーボード・マウス・ゲームコントローラー(ボタン 8・十字キー)・メディアキー / インターフェース 1 = 設定の口(8 バイト) |
| 割り当て | スイッチ 1 = a・**スイッチ 2 = F24**(センサーはここにつながる。元は b)・スイッチ 3 = c。センサーの記憶に残る(USB の抜き差し・PC の再起動の後も F24 のまま。実機確認) |
| 動き | **磁石が近い = オン**(F24 を押したまま)。センサーが送るのは「押した」「離した」の 2 回だけで、押している間の連打(約 30 ms おき)は Windows が作る |
| 副作用 | 連打は Windows に操作として数えられる(`tests/sensor/idle_check.py` で実機確認)。**オンの間は PC がスリープ・自動ロックに入らない**。文字は入らない |
| 道具 | `tests/sensor/sensor_config.py`(割り当ての読み書き)・`sensor_monitor.py`(オン / オフを見る窓)・`idle_check.py` |

- ゲームコントローラーのボタンに割り当てられれば、連打もスリープの副作用も無くなる見込み。ただし割り当てのバイトは資料に無い(メーカーの FootSwitch 7.4.4 で設定できれば、`sensor_config.py` で読み出して分かる)。
- キーの種類 0x81(連打なし)は、押してすぐ離す動きになる見込みで、離れたときが分からなくなるので使わない。
- 前提: 磁石は蓋の側、センサーは本体の側で、**蓋を閉じるとオン = 許可**。逆の付け方なら、オン / オフを入れ替える。

## 決まり

| 場面 | 動き |
|---|---|
| 蓋が開いている・センサーが無い・状態が分からない | **不許可**。「自動計測」「再計測」「再開」を押せない。状態の欄に「蓋：開」「蓋：センサーなし」の行(入力の不備と同じ出し方) |
| 照射の直前(1 回ごと) | 蓋が閉じているかを確かめてから `op.trigger()`。開いていれば照射しない |
| **照射中に蓋が開いた** | **すぐトリガーを離す**(今の「停止」と同じ道)。その回は失敗にしてセットを終える(決めごと 1) |
| 切替・設定の途中に蓋が開いた | 照射しない。セットを止める(決めごと 2) |

### 決めごと(2026-11-20 ユーザーの判断: おすすめのとおり)

1. 照射中に蓋が開いた回の台帳の扱い → **新しい失敗「蓋開放エラー」**(`am.FAIL_LID`。止めた理由が後で分かる。停止と同じく、機器の時間が設定どおりなら有効)。
   - 2026-11-20 ユーザーの判断で **「機器エラー」にまとめた**(`am.FAIL_DEVICE`。機器の時間が設定どおりなら有効なのは同じ)。蓋が開いているときの状態の欄は「蓋なし / 蓋とセンサーを確認してください」(`UI.LBL_LID_OPEN`)。
2. 切替・設定の途中に開いたとき → **セットを止める**(照射しない・台帳に入れない。済みの回があれば「再開」。押すと照射の確認がもう一度出る)。「閉じたら自動で続ける」はしない(試料を入れ替えて閉じた瞬間に確認なしで照射が始まるため)。
3. センサーをつないでいない PC → **センサーが無ければいつも照射しない**(設定で外す仕組みは作らない。CLI の `--plan` も同じ)。

## 作り

### センサーの読み取り: `src/lid_sensor.py`(新しく作る。画面を持たない)

- **専用の糸**が見えない窓(`HWND_MESSAGE`)で Raw Input(キーボード、`RIDEV_INPUTSINK`)を受ける。送り元の機器名が `VID_413D` の F24 だけを数える(`tests/sensor/sensor_monitor.py` と同じ作り)。ctypes だけで、パッケージは増えない(exe もそのまま)。
- 連打 1 回ごとの仕事は「最後に届いた時刻を書き換える」だけ。
- 状態は 閉(オン)/ 開 / なし の 3 つ。オフになるのは「離した」が届いたとき(すぐ)か、連打が 0.6 秒途絶えたとき。USB が無い・知らせが途絶えた・分からないときは閉にしない(照射しない側に倒す)。0.6 秒の見張りも糸の中で行う。
- **画面・測定の処理へ知らせるのは、状態が切り替わったときだけ**(閉 → 開・開 → 閉)。
- 照射中に開へ切り替わったら、その場で `auto_measure.CANCEL` を立てる(`_wait_result` は `CANCEL.wait` で待っているので、最大 3 秒の待ちを待たずに起きて、今と同じ処理でトリガーを離す)。止めた理由は「蓋」と分かるように持つ(`_run_step` の cause)。

### 測定の処理: `src/auto_measure.py`

- `measure` の `op.trigger()` の直前で、蓋が閉じているかを確かめる(開なら照射せずに中断)。
- 照射中に開いた回は `_judge` → `failure(…, cause=…)` で決めごと 1 の失敗にする。

### 決まり: `src/app_rules.py`(Tk 版・WebView2 版で共通)

- ボタン(`main_button`)と入力の不備(`input_issues`)に蓋の状態を足す。Tk 版(`measure_gui.py`)と WebView2 版(`controller.py`)の両方を直す。

### F24 の連打でアプリに負荷をかけない

- 今のアプリで負荷になるのは、**Tk 版の測定モード表のフェーズの入力欄**(`gui_modes.py` の `<KeyRelease>` → `_typed` → `_check_inputs` → 状態の欄の描き直し)だけ。欄を選んだまま蓋を閉じると、1 秒に約 30 回走る。ほかのキーの処理(Enter・Esc・Delete など)・値が変わったときの処理(StringVar の trace・`input` の知らせ)は F24 では動かない。WebView2 版のキーの処理は名前を見てすぐ終わる。
- **Tk 版は F24 を全部の窓でまとめて捨てる**(1 か所に置き、あとで欄を足しても同じにする)。WebView2 版もキーの処理の最初で `F24` なら何もしない。
- 状態の欄の文言が前と同じなら描き直さない。
- やらないこと: 低レベルのキーボードフックで F24 を Windows 全体から捨てる(処理が 0.3 秒ほど遅れると Windows が知らせずに外し、センサーも読めなくなる。キーを盗み見るソフトと同じ仕組みで、ウイルス対策ソフトに疑われる)・Windows の連打の速さを変える(ふつうのキーボードにも効く)・アプリだけキーボードのふつうの知らせを止める(ふつうの入力も止まる)。

### テスト

- 偽のセンサー(状態を手で切り替えられる)で、閉 → 照射 → 途中で開く → トリガーを離す・開いたまま押せない・センサーなしは押せない・切り替わりだけ知らせる を確かめる。`measure_logic_test`・`core_test`・`controller_test`・`gui_smoke_test` に項目を足す。
- デモ版の「デモの操作」に「蓋を開ける / 閉じる」を足す。

## 実機で起きたこと(2026-11-20)

- No.854(照射 2 秒目に蓋を開けた): すぐ結果画面になり、機器の時間 1.0 秒・「蓋開放エラー」。問題なし。
- 11:32 の回(照射 4 秒目に蓋を開けた): 命令まで 0 ms・離れた知らせまで 695 ms で止めたが、結果画面にならず測定中の画面のまま約 70 秒、機器に結果は残らなかった。その後メイン画面でもトリガーが NOT_READY のまま(本体のトリガーも反応しない)で、**機器の再起動でだけ戻った**。原因は不明(アプリの「停止」でも同じ TRIGGER_RELEASE を送るが、2026-11-13 の照射 1 秒・14 秒の停止では起きていない)。

## 止めるまでの遅れ(2026-11-20)

- 内訳: ① 磁石が離れてからアプリが受け取るまで(測っていない)/ ② 受け取ってから止める命令まで(0〜19 ms。センサーの糸からすぐ送るようにした)/ ③ 命令から機器が離れたと知らせるまで(約 0.4〜1.0 秒。機器の側でソフトでは縮められない見込み)。ログに「止める命令まで・OK まで・離れた知らせまで」を残す。
- これより速くするには、仕組みで止める・開けさせない方法(センサーの付け方で少し開いた時点で切る・照射中は電磁ロックで開けさせない・機器のインターロック。Bruker に要確認)。

## 組み込む前に実機で確かめること

- 蓋を閉じたまま、ふだんのキーボードで何か打っても、センサーのオンが続くか(Windows の連打が別のキーで途切れると、開に見えて測定が止まる)。
- PC の画面をロックしたときも、センサーの入力が届き続けるか。
- Tk は F24 の連打のたびに「離した」も出すか(上の負荷の見込みの確認)。
