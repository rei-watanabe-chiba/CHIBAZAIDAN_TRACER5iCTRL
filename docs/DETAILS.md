# Traer5iAuto: 決まりの細部(CLAUDE.md の詳しい版)

> 2026-11-25 まで CLAUDE.md だった全文。要点は CLAUDE.md にあり、ここは細部・経緯・実機で確かめた数値。決まりを変えたらここも直す。

Bruker の蛍光X線装置(USB RNDIS 接続、機器 IP 192.168.137.139)を、PC 上の **Bruker RemoteCTRL.exe** の画面越しに自動操作する。
目的は「測定 → 測定終了後にアプリケーション(モード)切替 → 再測定」の繰り返し。ユーザーとのやり取りは日本語。

## 配布

- **exe で配る場合**: `python tests/build_exe.py`(先に `python -m pip install pyinstaller`)で `dist/Traer5iAuto/` ができる。フォルダごと配る。
  - exe で起動したときは、exe のあるフォルダが基準になる(`storage.base_dir` / `use_base`)。`config` と `TracerData` は exe の隣に作られる。
  - exe に `--selftest` を付けると、機器を探さずに起動を確かめて `config/web_selftest.txt` に書いて閉じる(別の PC の確認用)。配布先に WebView2 Runtime が要る(Windows 11 は標準)。WebView2 のキャッシュは `config/webview/`。大きさは約 46 MB。
  - 1ファイル形式にしない・numpy と OpenCV と winrt と Tk を外す・画面(src/web)と照合の見本(src/screens)を含める(理由は build_exe.py の冒頭)。
  - 配布先に Python は不要。WebView2 Runtime・機器の USB のドライバー(Bruker Toolbox)・機器の接続は必要。署名の無い exe なので SmartScreen の警告が出ることがある。

- **配布するのは `Traer5iAuto/`(中身は `start_measure_gui.vbs` と `src/` だけ)**。フォルダごと移せばよい。`config/` と `TracerData/` は初回起動時に自動で作られる(`save_settings` / `LedgerBook` / `append_log` が `makedirs` する)。
- 配布先に必要なもの:
  - Windows 10/11(日本語の言語パック・OCR は不要。画面は見本との照合で読む)。
  - Python 3.14(`pythonw` が PATH にあること。VBS は `pythonw` で起動する)と `requirements.txt` のパッケージ(pillow・pywebview・pythonnet。winrt = OCR は見本を作るときだけ。OpenCV・numpy・Tk は使わない)。WebView2 Runtime(Windows 11 は標準)。
  - 機器への USB RNDIS 接続(画面・操作は TCP 55100〜55102 に直接つなぐ。取り込みは TCP 55000)。RemoteCTRL は不要(つないでいたら閉じておく)。Instrument Tools も終了しておく。
- PASS は `config/gui_settings.json` の `pass` にそのまま(暗号化せず)保存する(2026-11-10 ユーザーの判断。DPAPI はやめた)。`config/` を渡すと PASS も渡るので、配る前に消すか空にする。前の版の `pass_enc` は読まないので、入力し直す。
- 機器の画面の座標は届いた画面(480x640)で解析するので、窓の大きさ・画面の DPI に関係しない。窓の見た目の大きさは、起動時に選ぶ全体の倍率(`UI.ZOOMS`、下の「GUI の約束ごと」)で画面に合わせる(配布先での確認は未実施)。

## 安全ルール(厳守)

- **X線照射(トリガー / F6 / WM_COMMAND 40011)を、ユーザーの明示的な同意なしに送らない。** 測定の実行はユーザーが行う。照射を伴わないテスト(`--check`、`--switch-only`、状態の読み取り)だけを使う。
  - 例外は無い。放射線の注意の画面(電源を入れた後の最初のログインのあと「トリガを引いて放すと続行します」)も、アプリからは送らない(2026-11-12 実機: 機器はアプリからの `TRIGGER_PULL` / `TRIGGER_RELEASE` に反応せず、本体のトリガーを手で引いて放す必要があった。一時的に入れた確認のトリガーの機能は取り除いた)。
- **PASS をエージェントが入力しない。** PASS は `gui_settings.json` の `pass` に平文で保存している(ユーザーの判断)。エージェントは読み出して表示・送信しない。
- **画像を溜めない。** キャプチャはメモリ上だけで扱う。保存するのは異常時の `config/last_error.png`(上書き)だけ。例外: 見本に無い画面(`config/new_screens/`、最大 40 枚)。
- **蓋が閉じていなければ照射しない**(2026-11-20 ユーザーの判断。LID_SENSOR.md)。蓋のセンサーが無い・読めないときも照射しない(外す設定は作らない)。照射中に蓋が開いたらすぐトリガーを離す。ソフトの側の安全装置で、本体のトリガーを手で引けば照射できることは変わらない。GUI のテストは `lid_sensor._SENSOR` に `lid_sensor.Fixed` を入れ、本物のセンサーを読まない。
- 機器の表示設定(ズーム 1X/2X/3X など)を変えたら、元に戻す(既定は 1X、コマンド 104)。
- テストでは、本物の `config/` と台帳を書き換えない。設定のパス(`WebApp(settings_path=…)`)・`am.LOG_CSV`・`am.ERROR_PNG`・`am.TRACER_DIR`(保存先)・`am.LEDGER_STORE` を一時フォルダに差し替え、機器は偽の機器(`tests/demo_device.py` の `install`・`device_core.connect_link` / `find_devices` の差し替え)だけにする。

## 機器の操作の仕組み(画面の解析は RemoteCTRL のときと共通)

> この節の初めのほう(窓クラス・キャプチャ・メッセージでの入力・`read_ui` の OCR)は、2026-11-25 に消した RemoteCTRL の窓を相手にする処理の記録。今のアプリは機器へ直接つなぎ(下の「機器へ直接つなぐ」)、画面は見本との照合で読む。名前の照合(`same_name`)・ボタンの検出は `screen_ui.py`、OCR は `tests/ocr_read.py`(見本を作るときだけ)。

- 窓クラスは `S1RemoteHostClass`。**DPI 非対応**の窓。
- **キャプチャ**: `PrintWindow` で取得する(他の窓が重なっていても撮れる)。
  - DPI 非対応のため、論理サイズ分の左上を切り出して NEAREST で拡大する。
  - 最小化中は `SW_SHOWNOACTIVATE(4)` で、アクティブにせず元に戻す。
- **入力は前面化せず、メッセージで送る**(GUI がフォーカスを持つと F6 キーが届かなかったため)。
  - トリガー: `PostMessage WM_COMMAND 40011`。状態はメニュー文字列(`GetMenuStringW`)の pull / release で判定する。
  - クリック: `WM_LBUTTONDOWN/UP` を物理クライアント座標で送る。実マウスは動かさない(`SetCursorPos` は誤タップの原因になったので使わない)。
  - メニュー 107「Send all mouse move」はメッセージでは切り替えられない。触らない。
- **画面解析**(`read_ui`): 幅 `REF_W=960` に正規化してから処理する。
  - 青ボタンを Pillow で検出し(青の抜き出し → 9x9 の膨張・収縮で文字の穴を埋める → 行ごとのランでかたまりを求める `_components`)、文字は Windows OCR(winrt, ja)で読む。
  - 画像処理は **Pillow だけ**(配布を軽くするため OpenCV・numpy は使わない)。ボタンの文字は大津の2値化(`_otsu`)で白地に黒文字にしてから読む。
  - **機器の画面は左上に固定の大きさ**(ズーム 1X で幅 `NATIVE_W`=480 論理px。DPI 200% ならキャプチャで 960px)。窓を広げても右・下に白い余白が増えるだけ(2026-11-10 実機で確認)。
    - `read_ui` はキャプチャの左上から機器の画面の幅(`content_width()`)だけを切り出して `REF_W` に正規化する。下の余白は白いだけなので残す。
    - クリック位置は `ui.scale`(機器の画面の幅 / REF_W)を掛けるだけ(窓の大きさによらない)。
- **OCR の誤読への対策**:
  - 例: 設定→似定、OK→"0 K"、戻る→屎る。
  - `_match_score` / `same_name` で、あいまい一致と紛らわしい文字(0/O、1/l/i、5/S)を吸収している。
  - **名前に数字を含む場合は厳密一致**にする(Precious Metals 1 と 2 の取り違えを防ぐ)。
- **画面の状態**(`Operator.state`): main / login / startup / select_app / confirm / settings / keypad / result / measuring / unknown。
  - **電源を入れてからの流れ**(2026-11-12 実機で記録): 電源オン → 約55秒で USB のアドレス・ping・画面(55102)が同時に使えるようになる(このとき画面は「初期化中」と進行のバー)→ 初期化が終わる → 起動画面 → ログイン → **放射線の注意**(「トリガを引いて放すと続行します」。電源を入れた後の最初のログインのときだけ。ユーザーによれば、ここでトリガーを引いて放しても X線は出ず、確認の操作だけ)→ 現在の構成(OK)→ メイン画面。取り込み(55000)は ログイン画面のころに開く。トリガーの状態の知らせはメイン画面になるまで来ない。
  - アプリでの扱い: 初期化中(状態 booting)=「⌛ 起動中 / 機器の初期化を待っています」で、起動画面になるまで `UI.BOOT_POLL_MS` おきに静かに読み直す(「確認中…」を出さない。常時キャプチャしない決まりの例外)。起動画面・ログイン画面 =「⚠ ログイン待ち」。放射線の注意(状態 safety)=「⚠ 安全確認待ち / 本体のトリガを引いて放してください」で、手で操作されるまで同じく数秒おきに読み直し、次の現在の構成は読み直しの中で OK を押してメイン画面(準備OK)へ進める。「ログイン」ボタンで 起動画面の「ログイン」→ PASS でログイン(ログインの後が注意の画面・現在の構成でも成功)→ 注意の画面なら手の操作を待つ。測定の処理(`to_main`)は起動の途中・注意の画面では進めず機器エラー。
  - startup は電源を入れて機器の OS が起動した直後に出る画面(BRUKER のロゴ・「初期化 - 準備完了」・「ログイン」)。「ログイン」を押すとログイン画面になる(`open_login`。PASS は入れない)。GUI では「ログイン待ち」と同じ扱いで、「ログイン」ボタンで 起動画面 → ログイン画面 → PASS でログイン まで進む。`to_main` も起動画面なら「ログイン」を押す。
  - settings(設定画面)は「時間」の文字を含むので、measuring より先に判定する。
  - result の判定は「平均化」と「平均を計算」の両方のボタンで行う。
- **ログイン**:
  - テンキーの数字は OCR で読めない。CLR と DEL を手がかりに、同じ大きさの12個のボタンを位置で `"123456789C0D"` に割り当てる。
  - ログイン画面は、起動時と、測定後しばらく無操作のときに出る(測定中は出ない)。
  - **GUI でログインするのはボタンの「ログイン」だけ**(2026-11-10 ユーザーの判断。2026-11-12 にボタンの名前を「再接続」から「ログイン」に変えた)。ログイン画面では開始できず(`UI.STARTABLE` は準備OK だけ)、開始・測定の途中でも自動でログインしない(`am.PASSCODE` を空にして始める。途中でログイン画面になれば中断「ログイン待ち」)。CLI の `--login` / `--plan` は設定の PASS でログインする。
- **アプリ切替**: アプリケーション → 一覧から選択 → OK → 「現在の構成」画面 → OK → 名前を確認。
- **測定の待ち方**: 機器は設定時間で自動停止する。結果画面になるまで確認を続ける。
  - 確認間隔は、設定時間までは 3 秒、過ぎたら 1 秒。
  - 安全上限は、設定時間 + `SAFETY_EXTRA_S`(600 秒)。
  - 終了後にトリガーが引かれたままなら離す。
  - **トリガーを引いたあとは、どんな理由で中断しても(停止・時間超過・画面の異常・予期しない例外)トリガーを離す**(`measure` の try/except BaseException)。
  - 測定の前からトリガーが引かれていたら、手で操作中とみなして照射せずに中断する(`ManualTrigger`)。開始前の状態確認でも「手動動作中」として開始しない。
  - 測定が終わったら、次のモード切替(最後はメイン画面への戻り)の前に `SWITCH_WAIT_S`(2 秒)待つ。すぐ切り替えると機器がエラーになる。
  - **終了は画面で判定する**(結果画面になったら終了)。表の秒数は確認間隔・進捗・安全上限だけに使う。
  - 結果画面から、ファイル No(`^(\d+)\d\d-\d\d`)と機器の測定時間(「時間」の後ろの数字)を読む。
- **測定時間の書き込み**(`set_phase_times`): メイン画面右上の「設定」→ 各フェーズの時間欄を押す → テンキー画面で クリア → 数字 → OK → 設定画面の OK。
  - 時間欄は各フェーズの [-] [+] ボタンの間。Spectrometer Mode は「期間」の右の欄。
  - テンキーのボタン群は1つの塊として検出されるので、塊の中の相対位置(`KEYPAD_COLS/ROWS`)で押す。
  - 値が同じなら書き換えず、キャンセルで閉じる。書き換えたら OCR で表示を確かめてから OK。
  - 欄の数値は、画面全体の OCR では欄の枠に邪魔されて拾えないことがある(取り込み中の実機で毎回起きた)。そのときは欄の内側だけを切り出して読み直す(`field_value(ui, f, ocr)`、`FIELD_INSET`)。
  - 「デフォルト設定を使用」がオンで時間欄が無いときは、チェック欄を押して外してから書き込み、OK で保存する(`_turn_off_default`)。
    - チェック欄は文字の左。オンのときは文字に点線の枠が付き OCR の位置が左へずれるので、決め打ちの距離ではなく画素から欄の両端を探して真ん中を押す(`checkbox_left_of`。見つからなければ `DEFAULT_BOX_DX`)。
  - 外しても時間欄が出ない、またはフェーズ数が測定モードの設定と違うときは、キャンセルして中断する(機器エラー)。
  - 整数秒のみ(62.5 は確認できなかった)。
  - 「計測時間を毎回設定」(`set_each`。GUI のチェックボックスは逆向きの「フェーズ設定をスキップ」(チェック = オフ)・保存あり、CLI は `--no-set` でオフ):
    - オン: 各測定の前に、そのモードの設定画面へ書き込む(値が同じならキャンセルで閉じる)。
    - オフ: 設定画面を開かず、表の時間を目安に待つ。
  - どちらでも、結果画面の機器の測定時間と表の時間がずれていたら(`time_mismatch`)、終了まで待ってから アラート欄に「設定 30 秒 / 機器 26 秒」の形で出す。

  - **生存の知らせ**: 機器はつながっている間、約 1.1 秒ごとに 0x19 を送る(2026-11-12 実機で起動画面のときも 1.1 秒ごとと確認)。`ALIVE_TIMEOUT_S`(5 秒)来なければ切れたとみなし、接続を閉じる(`DeviceLink._watchdog`。エラーが返らずに黙って途絶えると受信を待ったまま気づけないため)。**生存の確認は 55102 だけで行う**(55101 は状態が変わったときだけ知らせ、55100 は返事だけ。3本とも同じ USB を通る)。USB を抜いたときは Windows がその瞬間に接続を切る(10053 / 10054)ので、5 秒を待たずに気づく(2026-11-12 実機)。初期化中は知らせの間隔が 2〜3 秒に延び、初期化の終わりに約 7 秒止まって、同じ接続でまた届く(切れない)。画面の更新も生きている知らせとして数える。初期化中(`booting`)の上限は `BOOT_ALIVE_TIMEOUT_S`(30 秒)。長く止まった後にまた届いたら、止まっていた長さをログのファイルに残す(`GAP_NOTE_S`)。
  - **本体画面は、つながったらすぐ表示する**(見本との照合とは関係なく、届いた画面をそのまま出す)。画面を読む処理(状態の確認・測定)は、まだ1枚も届いていなければ `FRAME_WAIT_S`(10秒)待つ。接続の様子(つながった・つながらない理由・切れた理由)は、ログのファイルに残す(`DeviceWatch.note`)。
  - **トリガーの接続(55101・55100)**: つなぐときに1回だけ試し、だめなら裏で試し続ける(断られたら `SUB_REFUSED_RETRY_S`(1秒)おき、それ以外は `SUB_RETRY_S`(3秒)おき)。断られても画面の接続は切らない(機器の初期化の途中は 55102 だけが開いていて、55101・55100・55000 は初期化の終わりに同時に開く。2026-11-12 実機)。**つないだ後に切れたとき**も、画面の接続は保ち(本体画面は出し続ける)、その接続だけをつなぎ直す(`DeviceLink._sub_lost` / `_sub_retry`。つないでいる間に画面の接続が閉じたら、つながったトリガーの接続は残さず捨てる)。それまでトリガーの状態は不明(照射できるか分からないので測定は始めない)。**55101・55100 も前と同じ PC 側のポート番号でつなぐ**(`DeviceLink.sub_ports`、`_open_sub`。55102 と同じ理由: USB を差し直すと新しい番号では 55101 が約 3 秒断られ続けた。その番号が PC 側でまだ使えなければ(10048 / 10049)新しい番号で。切れたトリガーの接続はすぐ捨てる)。2026-11-12 実機: 電源を入れた直後などに、機器がトリガーの状態の接続を、つないで約 1.6 秒で切ることが続いた(最初の画面の後につないでも起きた。電源を入れてしばらくたったログイン画面では起きなかった)。起動の途中の機器は、ping が通って接続(TCP)は受け付けても、機器の情報を送ってくるまで時間がかかるので、情報は同じ接続のまま `INFO_WAIT_S`(60秒)待つ(待ちきれずに切ってつなぎ直すと、機器は前の接続の後始末が終わるまで答えない)。
  - **接続の受け持ち**: GUI では、機器につなぐのは本体画面の「接続」だけ(`device_core.connect_link` = `shared_link(connect=True, host=…)`)。状態の読み取り・測定は、つながっていなければつなぎに行かず「機器につながっていません」(未接続)にする(`device_link.AUTO_CONNECT = False` を web_app が設定。CLI は今までどおり自分でつなぐ)。切れたときは、どの接続(画面・トリガーの状態・命令)が、つないで何秒で切れたかをエラーの文に入れる。
  - 接続はアプリで1つ(`shared_link`、つなぐのに約5秒)。つなぐ前に機器がいるか ping で確かめ、いなければすぐ「機器が見つかりません」(`CHECK_PRESENT`。USB が無いと接続が Wi-Fi 側へ流れ、10 秒×2 待っていた)。待ち受けで機器は見つかったのにつながらないときは、理由をログのファイルに残す(`DeviceWatch.note`)。機器の状態の欄が変わったときも、ログのファイルに「[状態] …」を1行残す(画面のログには出さない)。つなぐのに失敗したら(拒否以外)、その場ではつなぎ直さない(機器が前の接続の後始末を終えるまで答えないため)。閉じるときは `shutdown.release_trigger`(照射中なら止める)→ `close_link`(ふつうに閉じる)。切れた・失敗したときは3本ともすぐ捨てる(リセット。`DeviceLink.close(abort=True)`、`_fail`)。
  - **切れたときのつなぎ直しと測定の再開**(2026-11-12 実機の検証にもとづく。ユーザーの判断):
    - **前と同じ PC 側のポート番号でつなぐ**(`DeviceLink.local_port`、`_open(…, local=…)`、`SO_REUSEADDR`。使えなければ新しい番号)。USB を抜いたとき機器の情報を待つ途中だった接続は機器に残り、新しい番号では 3〜6 分断られ続けたが、同じ番号なら機器が前の接続を片付けて 1 回目で受け付けた(差してから 7.6 秒)。安定してからなら約 5〜8 秒、別の USB の口に差し直しても同じ(PC 側のアドレスは 192.168.137.45 のまま)。そのため切れた接続は、PC 側にその番号の名残を残さないよう、すぐ捨てる。
    - 本体画面: 切れたら最後の画面にグレーをかけて残して一覧・「接続」に戻し(上)、同じ機器が戻れば自動でつなぎ直す(同じ LINK なので前と同じポート番号)。アラート欄に「機器との接続が切れました / 同じ機器がつながれば自動でつなぎ直します…」(`UI.RECONNECT_NOTE`)。
    - **照射の途中で切れたとき(2026-11-14 ユーザーの判断: 停止と同じ扱い)**: USB が切れると機器は照射を止めるので、つなぎ直す(同じ機器が戻れば自動)のを待ってその回の結果(No)だけを読み、その回は失敗「接続エラー」にして**ターンを終える**(`am.CutStop`。測り直しは聞かない・次のモードへ進まない・ログインも待たない)。切れている間の状態の欄は「照射停止 / USB を確かめてください(つなぐと結果を読んで終了)」(`UI.RESUME_WAIT["cut"]`。照射は止まっているので停止は押せない。`RESUME_WAIT_S` つながらなければ「接続切れ」で中断)、つないだ後は「結果確認中」(照射の進み具合は出さない)、終わったら「接続切れで停止」。本体画面は結果画面のまま → 済みの行があれば結果画面のまま「再計測」で未了(切れた回と後の回)を測る。結果を読んだら照射は最後まで終わっていた(ソフトの側だけ切れたなど)ときは、ふつうの結果としてそのまま続ける。
    - **照射の前(切替・設定の途中)に切れたとき**(`auto_measure.run_plan`): 中断せずに、つなぎ直す(同じ機器が戻れば自動)まで待って、その回をはじめからやり直す。状態の欄は「接続切れ / つなぎ直すと続きから再開」(`UI.RESUME_WAIT`、`Controller._on_wait`)。`RESUME_WAIT_S`(600秒)つながらなければ「接続切れ」で中断。1回の測定で `RESUME_MAX`(3)回まで。つないだ接続への付け替えは `DirectRemote.relink`: 本体画面で「接続」した接続(`dl.IN_USE`)で、前と同じ製造番号のときだけ(自動で確かめている途中の接続・別の機器では再開しない。RemoteCTRL の窓では再開しない)。
      - その回がどうなったか(`resume_step`): 照射の前(切替・設定の途中。`STEP["t0"]` が無い)なら、その回をはじめからやり直す。照射を始めた後なら、画面が測定中・結果画面ならそのまま続ける。結果画面が消えていたら(ログイン画面など)、機器の結果表(`Results.csv`、`instrument_files.results_rows`)で、開始のときの最後の No(`Controller._last_no`。測定が終わるたびに進める)より後の行を探す: 1行でアプリ名が同じなら、その回の結果(No = File #、時間 = ElapsedTime。時間のずれも判定)。無ければ照射されていないとみなしてやり直す。2行以上・アプリ名が違えば機器エラーで中断。引かれたままのトリガーは離す。
      - 次の回へ進む前(`ensure_ready`): ログイン画面・起動画面なら「ログイン待ち / 「ログイン」で再開」にしてボタンを「ログイン」にする(押すと `am.request_login` で PASS を渡し、測定の処理がログインして再開。**ログインは「ログイン」ボタンからだけ**の決まりのまま。本体で手でログインしても進む)。初期化中・放射線の注意なら手で進めるのを待つ(数秒おきに読み直す)。ログイン画面で待っている間はボタンが「ログイン」なので、停止はできない(アプリを閉じる)。
      - 2026-11-12 ユーザーの測定(No.771〜774)で確認: **USB の接続が切れると、機器は照射を止める**(本体で確認)。その回は短い測定(例: 設定 30 秒 / 機器 8 秒)として結果画面と結果表に残り、再開すると「測定は終わっていました」としてその No を読み、計測時間誤差のアラートで知らせる。**途中で止まった回を測り直すかは保留**(2026-11-12 ユーザーの判断。測り直すとファイル番号が変わり、台帳の入力の重複の判定にも関わるため、扱いを検討してから)。結果表の ElapsedTime は結果画面の「時間」と同じ値。**Spectrometer Mode の回は結果表に行が無い**(pdz はある。2026-11-13 実機)ので、`results_rows` は機器の pdz の一覧も読み、結果表に載らない回を時間なしの行(モードは pdz の名前から)として足す(その回を再開で読むと、時間が分からないので失敗「接続エラー」)。**ソフトの側で TCP を切っても機器は照射を止めない**(設定の時間まで照射する。2026-11-13 実機。USB を抜いたときだけ止まる)。
  - 機器は同時に1つの相手としかつながらない。アプリがつないでいる間は RemoteCTRL ではつなげない(逆も同じ。つながらなければ本体画面の「接続」でつなぎ直す)。
  - 「機器の画面」の枠: 届いた画面(480x640)をそのまま canvas に描き、大きさは CSS で左の列の幅に合わせる(縦横比 3:4。窓の大きさが変わればブラウザーが伸び縮みさせる)。解析は届いたままの 480x640 で行うので表示の大きさに関係しない。枠の中のクリックを機器へ送る(手で操作できる)。自動測定の間は手で押せない(`manual`)。上の行に、つながっているか・照射できる状態か(`UI.TRIGGER_LABEL`)。
  - RemoteCTRL の窓を相手にする予備の処理(`bruker_ui.RemoteCtrl`・CLI の `--remotectrl`)は 2026-11-25 に削除した(取り込み・起動・自動接続の処理は 2026-11-10 に削除。経緯は CHANGELOG)。
  - テストは偽の機器(`tests/fake_device.py`・`tests/demo_device.py`)を使う。`device_core.connect_link` / `find_devices` を WebApp を作る前に差し替え、本物の機器につながない。
- OCR はイベントループを使い回し、`SoftwareBitmap` と `DataWriter` を close する(メモリ増加の対策済み。600回読んでもメモリは横ばい)。

## GUI の約束ごと(2026-11-20 に Tk 版から WebView2 版へ切り替えた)

- **作り**: 窓は pywebview(WebView2)。画面は `src/web/`(`index.html`・`app.css`・`app.js`・`right.js`・`table.js`)。決まりはすべて Python の側(`controller.py`・`device_core.py`・`*_core.py`・`app_rules.py`)にあり、画面は届いた知らせを映して操作を返すだけ。
  - Python → 画面: `Bridge.emit(種類, 中身)`(順番どおり・`SEND_BATCH_MS` の間に来た分をまとめて送る。本体画面の絵・状態の欄など最後の 1 つだけでよいものは `replace=True`)→ `app.receive` → `app.on(種類, …)`。
  - 画面 → Python: `pywebview.api.…`(`web_app.Api`。名前が _ のものは画面に見せない)。中身の処理は `Bridge.run` で 1 本の「画面の糸」に渡して順に行う。**アプリの状態を変えるのはいつもこの糸だけ**(裏の糸からは `post`)。
  - 閉じるとき: 測定中なら確かめてから(`UI.CLOSE_CONFIRM_*`)、最初に画面へ送るのを止め(閉じていく窓へ送ると .NET のエラー)、測定を止め、照射中ならトリガーを離し(`shutdown.release_trigger`)、保存して接続を切る。止められなければ知らせる(`UI.CLOSE_FAIL_*`)。
  - 状態を読んでいる最中にボタン(「画面更新」「ログイン」「自動計測」)を押されたら、読み終わってから続けて行う(`Controller._queued`。押しても何も起きない、にしない)。
- **見た目の変更は `gui_config.py` の `class UI` だけで済むようにする。** `UI` の値はそのまま画面へ渡す(`web_app.ui_values`): `#rrggbb` の色と数は CSS の変数 `--名前`(数は px と `--名前-n`)、2 つ組の値は `app.js` の `applyUI` / `right.js` の `setupRight` で個別に、文言は `data-ui="名前"` の要素へ。`app.css` には並べ方だけを書く。文字の大きさは pt(px は 4/3 倍)。
  - **全体の倍率**(`app_rules.choose_zoom`): 起動時に1回、画面の作業領域(CSS の px)の高さに `UI.DESIGN_HEIGHT` が収まる一番大きい倍率を `UI.ZOOMS` から選ぶ(設定に `zoom` があればそれ)。`document.documentElement.style.zoom` に入れる。高 DPI は WebView2 が掛ける。
  - 起動時の窓は作業領域の `UI.WIN_FRACTION`(前回の大きさ `web_window` は画面に収まる範囲で使う。`place_in`)。最大化は `web_zoomed`。最小は `UI.WEB_MIN_SIZE`。窓の地 `UI.WEB_BG`(描く前の所もこの色)。
  - 最大化・解除・窓の大きさを変えても古い画面・黒い所は出ない(Tk 版で解消できなかった。2026-11-19 ユーザーの確認)。

- **停止は照射中だけ押せる**(2026-11-14 ユーザーの判断。押した時点ごとの分岐をなくすため)。照射中に止めたら: トリガーを離し、結果画面を読んで(`stopped_result`)、ふつうに終わった回と同じ決まりで判定する(`_judge` → `failure(…, cause="stop")`): 機器の測定時間が設定どおり(照射が終わる瞬間に押した)なら有効(行は ✓)、短い・読めなければ台帳に「✕ 停止エラー」(行は ✕ = 未了)、時間どおりでも表が空などは機器エラー。どちらでもターンはそこで終わる(後の行は ○ の未了)。本体画面は結果画面のまま残す(結果を見たいことがある)。状態は「結果画面 / 結果を確認したら「画面更新」」、ボタンは、未了があれば(台帳と組みにして済みの行がある)結果画面のまま「▶ 再計測」か「▶ 再開」と「終了」(説明は「結果を確認したら「再計測」(「再開」)」`UI.RESULT_PENDING` と未了の行。押すとメイン画面へ戻してから(`_refresh_status(to_main=True)`)照射の確認 → 未了を測る。2026-11-16 ユーザーの判断)、無ければ(済みが 0・全部済み)「↻ 画面更新」(メイン画面へ戻してセットを閉じる)→ 準備OK で「自動計測」。切替・設定の途中・再開を待つ間・取得中は止められない(止めたいときはアプリを閉じる: 照射中ならトリガーを離してから閉じる)。

## 照射前の確認

- **入力の不備**(2026-11-11〜。`Controller._check_inputs`): 測定モードが1行も無い・フェーズの入力欄の値が不正(`Modes.issues`)・計測情報の必須項目(`UI.REQUIRED_FIELDS` = Database・ID)が空・**計測済み**(開いているターンの行がすべて済み、または同じ計測ファイル・モードの有効な行が台帳にある。上の「ターンと再計測」。同じ試料をもう一度測るときは subID(枝番)を変える。必須項目が空のときは調べない)。開始ボタンを押したときではなく、**入力欄・表の値が変わるたびに**調べる(必須項目は打つたび、フェーズの欄は打つたび(`<KeyRelease>`)と確定のとき、表は行の追加・削除・モードの変更)。不備があれば「自動計測」「再計測」は押せない(灰色。入力で直ればすぐ押せる。`UI.MAIN_BUTTON_LOCK_MS` の待ちは機器の状態で「自動計測」「再計測」に変わったときだけ。入力・台帳の変化で「自動計測」⇔「再計測」が入れ替わるときは待たない)。台帳の行を選んでいても開始できる(「✎ 編集中」は 2026-11-16 に削除)。機器が準備OK のときは状態の欄を「✕ 入力エラー」(`UI.LBL_INPUT_ERROR`、赤)にし、説明に不備ごとに1行(`UI.INPUT_ISSUES`: 「モード：測定モードなし」/「モード：フェーズ入力不備」(行は欄の赤い文字で分かるので文に出さない)/「計測情報：Database・ID」(空の必須項目)/「計測情報：計測済み(subID を変更)」)。計測済みは subID などの入力・測定モード表の変化に加え、台帳の行の変化(測定の追加・編集・削除。`LedgerModel.save` → `on_rows`)でも調べ直す。機器が準備OK でないときは機器の状態を先に出す(ボタンは状態に合わせて ログイン / 更新 / 押せない開始)。直ると機器の状態(`Controller.dev`)に戻る。`start_measure` でも念のため調べ、不備があれば機器の状態確認や確認ダイアログには進まない。ダイアログ・アラートは出さない。

- 開始時の確認は 確認のダイアログ(`app.js` の confirm・`Controller.confirm_answer`。背景なしの赤い放射線マーク・「X線を N 回照射します」・安全確認のチェック1つ・色なしのボタン)だけ。チェックするまで「照射開始」は押せず、Enter・Esc はキャンセル。チェック済みかは閉じる処理の中でも必ず確かめる(ボタンの状態に頼らない)。
- 画面のテストはダイアログを画面に出す。テスト中に出たダイアログを人がクリックすると結果が変わりうるので、テストはボタンや変数を直接操作して判定する。安全確認以外の情報は載せない(ユーザーの要望)。
